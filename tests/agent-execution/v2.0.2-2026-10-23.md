# v2.0.2 execution, complexity and compatibility evidence

This release addresses the eight review topics through proportional execution,
compatible compact handoffs, observable capability checks and broader executable
measurement. It does not turn instruction text into an OS sandbox or establish
universal superiority over v1.2.1. Original failures and interrupted evaluations
are retained alongside successful reruns.

## Delivered behavior

All 24 independently installable skills distinguish read-only, reversible-local,
remote/shared and destructive/untrusted-execution effects. Routine local branch/tag
creation has an explicit short path; unrelated remote surveys, stashes and JSON
artifacts are unnecessary. Immutable object facts may be reused; mutable targets,
effective endpoint/configuration, protected state and scoped authority must be
revalidated. Wrong-destination, race, incidental tag/submodule publication and
unknown-outcome protections remain.

Compact checkpoint v2 has six mandatory fields plus applicable state. Full v1
checkpoints remain accepted; known preconditions, protected state, unknown effects
and recovery limits cannot be dropped. Interrupted/multi-ref workflows retain
per-effect journals and native-state reinspection. Conditional transport detail
ships inside each affected skill, with explicit triggers, preserving standalone use.

The optional runtime probe enforces only its own timeout/fsmonitor/optional-index
controls. It reports config categories without secret values and explicitly lists
unproven isolation capabilities. Requiring such a capability fails closed; actual
enforcement remains a runtime/operator responsibility. This is not an automatic
requirement for ordinary trusted local work.

## Benchmark design and bounded observations

The paired suite uses 16 native tasks plus 14 routing queries in one routing session:
30 observations across 17 sessions, not 30 independent conversations. It covers
ordinary branch/tag actions, staged selections, recovery, conflicts, stacks, split
endpoints, stale conditions, failed push, ambiguous destination and 3–4 intents.
Each native task has independent Git-state assertions. Refusal cases also require
trace/final-answer review: preservation alone does not prove a correct refusal.

On October 18, v1.2.1 and v2.0.1 were interleaved with a fixed shuffle, same model,
reasoning and invocation configuration. The initial v2.0.2 candidate used the same
runtime in a subsequent batch. Exploratory native-task measurements were:

| Candidate | Median wall seconds | Median shell calls | Native outcomes after scorer review |
|---|---:|---:|---|
| v1.2.1 | 35.50 | 5 | 16/16 |
| v2.0.1 | 42.40 | 6 | 16/16 |
| Initial v2.0.2, before targeted commit repair | 36.66 | 5 | 16/16 |

These are single observations under concurrent load, not latency guarantees or a
causal estimate. Final targeted repairs were re-evaluated; the table is deliberately
not relabeled as final-release performance. Input/output and cached-input usage are
retained per case; they include inherited/runtime context and repeated history.

The final native/routing coverage is assembled from completed runs and fresh reruns
of interrupted cases on `gpt-6.1-sol` and `gpt-6-luna`, both medium reasoning. Each
model completes the same 16 native tasks and 14 routing queries. Native classifications
are eleven safe successes and five correct blocking/refusal outcomes per model;
no unnecessary final refusal was observed in those eleven feasible tasks. This is
not a statistical false-refusal estimate. The standalone suite exercises one bounded
task for each of the 24 skills; the revised commit task additionally passes as a
standalone installation. Diagnostic skills include intentionally read-only tasks;
large-file coverage inspects pointer status, not a complete LFS migration.

The composition suite passes eight routing queries and six native tasks: existing
merge continuation and publish, unsafe conflict refusal, interrupted restack, lost
response reconciled to no-op, stale checkpoint refusal and selected commit/publish.
The oracles independently check parents, refs, draft/index bytes, completed-layer
reflogs and native sequencers. No new `.serena` directories were observed in the
isolated benchmark batches checked; this does not establish filesystem isolation.

## Defects and evaluation corrections retained

1. The first routing scorer rejected legitimate conditional conflict-resolution
   returns for cherry-picks, direct entry into an already stopped conflict, and a
   request for an omitted URL/tag parameter. Narrow alternatives now accept those
   plans; counter-tests still reject wrong owners, omitted intents, repeated execution
   and unsafe decisions. Original failed outcomes remain unchanged.
2. Windows Git objects are read-only. Standalone fixture creation initially failed
   before model execution when constructing an intentionally missing object. The
   fixture now changes only that verified disposable object's mode before unlinking.
3. A smaller-model trace created an out-of-scope commit, then amended it back. A
   correct final tree did not establish the protected-history invariant. The oracle
   now examines all new reflog commits; a counter-test rejects a repaired bad commit.
   The skill explains initializing an alternate index from HEAD, retaining excluded
   entries and reviewing the complete candidate tree.
4. A subsequent trace lost `GIT_INDEX_FILE` across tool calls. The skill now binds
   that environment in each Git invocation and checks its tree immediately before
   commit. Cleanup runs separately. Both models and standalone targeted reruns pass
   without intermediate out-of-scope commits. Runtime policy rejections in the failed
   prototype are retained; no policy was weakened to unblock execution.
5. Several October 18 final runs exhausted account quota. A nonzero model process is
   incomplete, even if a preserved-state oracle passes. Successful fresh cases from
   October 23 replace only coverage gaps; original traces/results are retained.
6. A literal-source CLI token probe produced inconsistent baseline subtraction,
   including a negative delta. It is rejected as source-token attribution evidence.
   The replacement meter counts exact source text under a named public encoding.

## Source cost and runtime limits

| Entrypoints, all 24 | UTF-8 bytes | Words | `o200k_base` tokens |
|---|---:|---:|---:|
| v1.2.1 | 157387 | 20949 | 30020 |
| v2.0.1 | 261279 | 35050 | 50919 |
| Final v2.0.2 | 259449 | 33862 | 50326 |

The last row's exact snapshot matches the delivered skill source and is retained.
These text counts use tiktoken 0.12.0, not a claim about the private tokenizer
or billing of either evaluated model. Conditional references are counted separately
in the source-cost results, rather than hidden as removed instructions. No large
context or universal speed improvement is claimed.

Original runs used Windows, Python 3.14.6, Git 2.56.0.windows.2 and Codex CLI
0.163.0-alpha.10.2; resumed runs use 0.163.0-alpha.11.1. Config isolation disables
discovered user/system skills, ignores user config and project instructions only
for that invocation. Auth/host policy still apply; all Git transports are disposable
local paths. The backend does not expose a resolved model identity. New sessions
and one CLI runtime family are not multiple independent operating systems/vendors.

This work cannot prove a model never stops unnecessarily, enforce host isolation,
exercise every standalone option, certify production readiness or test hosted
banking credentials/network policies. Those remain explicit deployment/evaluation
limits, not passing results.

## Verification and evidence

Mechanical validation includes 39 focused tests, Windows smoke 36, review regression
21 supported plus one safe refusal, recheck groups, skill/security validation and
all 24 skill-creator checks. The 14 new execution-profile tests also pass on actual
Git 2.35.0 in WSL. Workflow lint validates the new CI steps. Paid agent evaluation is
separate from deterministic CI.

[Evidence archive](evidence/v2.0.2-2026-10-23.zip) retains prompts, raw JSONL/stderr,
exact skill/resource snapshots and hashes, original process/oracle results, reviewed
verification, harness sources and runtime metadata. The final delivery manifest and
patch identify any post-evaluation metadata/source changes. Fixture repositories
remain local under ignored `artifacts/`; the archive is trace/assertion evidence,
not a portable copy of every Git object database.

Recheck a completed benchmark with no model calls:

```text
python tests/agent-execution/benchmark.py <retained-run-directory> --verify-only
```

For source-only measurement, `instruction_cost.py <new-directory> --candidate name=revision`
needs only the ordinary harness dependencies. `--encoding o200k_base` optionally needs
tiktoken; it is not a dependency of skills, runtime probes or ordinary CI.
