# Blind execution evidence, 2026-10-18

Twelve fresh Codex CLI sessions used the configured default `gpt-6.1-sol`, reasoning
`medium`, on Windows with Git 2.56.0.windows.2, Python 3.11.15 and CLI
0.163.0-alpha.10.2. The backend model ID is not emitted by this CLI; the configured
model was inspected during the run. Each session received one concrete request,
the candidate skill catalog/directory and local fixture scope. It did not receive
the fixture oracle, expected answers or prior conclusions. The host's existing
configuration, plugins and skill discovery remained active; this is not a clean-room
runtime or an isolated measurement of routing from candidate descriptions alone.

The base revision was `5063ad432b53e9e896c23ba1107b23bce3aa3779` with local changes.
Exact evaluated skill bytes, including catalog metadata at 2.0.0, and per-file hashes
are retained. Subsequent release preparation changes the catalog to 2.0.1; it does
not change the evaluated SKILL.md, reference or helper bytes. This is not evidence
for every file in a future release archive.

## Results

| Task | Observed result | Independent protected-state assertions |
|---|---|---|
| Selected commit | Supported: calculator snapshot committed | Notes index and unsaved draft retained |
| Unborn unstage | Supported: file unstaged, no invented commit | File bytes retained |
| Lost draft | Supported: additive rescued-ending branch | Original HEAD, index and dirty draft retained |
| Stack restack | Supported: B-only change rebased onto squash-landed main | A, main and unrelated anchor retained |
| Split push endpoints | Supported: only write endpoint advanced | Read endpoint and remote tags retained |
| Conflict continuation | Supported: merge completed with both settings | Merge parents, no unmerged stages or active merge |
| Read-only diagnosis | Existing refs/index/files retained | Tool-created metadata violates a strict no-new-files contract |
| Stale publication | Necessary refusal: exact old OID no longer matched | Intervening remote commit retained |
| Failed classifier | Necessary refusal: classifier always exited 127 | Checkout retained; no bisect session |
| Dirty branch creation | Supported: feature-copy created, checkout unchanged | Raw CRLF bytes and index retained |
| Symbolic tag | Necessary refusal: alias targets main | Alias and target retained |
| Rejected push | Necessary refusal after actual hook rejection and read-back | One push attempt, no remote policy changes |

All twelve process exits were zero and all twelve independent task/protected-state
oracles passed. Eight tasks reached their ordinary outcome and four correctly stopped.
Manual review of the recorded command sequences and final responses found zero
unnecessary approval/input stops. These are task-level observations, not statistical
estimates of general success rates.

**Unintended writes:** runtime tooling created `.serena/` in all twelve fixtures.
Thus zero of twelve runs meet a strict no-additional-files criterion, and the diagnosis
task must not be described as fully read-only at the runtime level. Existing user
data/refs passed the recorded invariants; these statements have different scopes.
No skill safety wording was added to hide or compensate for runtime initialization.

Aggregate CLI-reported usage was 2,253,336 input tokens, of which 1,961,472 were cached,
and 12,428 output tokens (1,033 reasoning output tokens reported separately). These
include inherited context and repeated turns, not just skill instructions. The complete
candidate skill snapshot is 272,926 UTF-8 bytes. No A/B reduction or isolated skill-token
measurement was performed; instruction shortening remains deferred pending that evidence.
